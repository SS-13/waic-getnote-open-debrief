## 一句话概要
把训练数据比作原油、把数据平台比作炼油厂——用自研存储格式、索引与高效 data loading，把参差不齐的多模态数据整整齐齐、源源不断地喂满 GPU，避免算力空转。

## 核心观点
- 深度网络提取数据信息如同挖石油：原油（原始训练数据）本身几乎没用，必须送进"炼油厂"加工才有价值。
- 使命是把参差不齐的数据高效整齐地投放到 GPU 上，解决 GPU 因数据读不上来而空转导致的算力浪费。
- 大数据时代的 Parquet 为顺序访问设计，对多模态随机采样会成为整个数据管线的 bottleneck。
- 数据的未来属于多模态，中国错过了 Oracle、Snowflake 时代，但这次有弯道超车的最好机会。

## 内容整理

### 石油与炼油厂的隐喻
用大规模深度神经网络提取海量数据里的有效信息，好比挖石油：磕头机挖出的原油就像训练数据，价值都在原油里，但原油本身几乎没用，需要送到炼油厂经一系列化学反应加工，才能生成有用的石油制品。问题是——这些参差不齐、收集上来的数据，如何整整齐齐地出现在 GPU 上训练模型？这正是团队要打造的"面向多模态 AI 应用的数据基础设施"：像现代石油工业的储油罐、输油管线一样，把参差不齐的数据源源不断、高效地投放到 GPU 上，彻底解决 GPU 因数据读不上来而空转、导致算力浪费与模型迭代拖延的问题。

### 数据平台架构
原始数据进入系统后先到**数据治理层**，其中的 Pipeline 算子都是可配置的（Configurable），按用户需求对原始数据做裁剪、清洗、打标，最后转换成团队自研、对多模态随机访问极其高效的格式（转写作 F4）。此后数据才真正进入系统被有效管理：**元数据层**管理其 Schema 与版本迭代，并对数据构建高效索引——对标签做精确索引、对 Embedding 做模糊索引，从而支持对训练集灵活筛选与数据配比。举例：想训练机器人在失去平衡时不要往人身上撞，就把所有"机器人摔倒"相关帧取出，tokenize、tensor 化后送 GPU。

### 性能瓶颈与判断
若 GPU 每秒需消耗 1000 个 sample，而整个数据链路（无论 bottleneck 在哪一步）只能提供 200 sample/秒，则这次训练 GPU 利用率最高只有 20%，是巨大浪费。团队在数据链路每个环节都做了提升：例如存储端若继续用大数据时代标准格式 Apache Parquet，随机采样就会成为 bottleneck——Parquet 为大量顺序访问设计、对多模态数据无感知，且会把相邻数据编码压缩成大块，随机读一个数据就要读一大块。对比中（橙线为 GPU 消耗 sample 速度）：用 Robot 原生 Data Loader 会浪费大量 GPU 算力（喂不饱 GPU），而用 Model Link 性能仍绰绰有余，且最终仿真成功率更高，说明其 Data Shuffle 算法最大程度保留了数据多样性与随机性。他判断：数据的未来一定属于多模态（体量、处理难度、可支撑产业多样性都是数量级提升）；中国错过了 Oracle、甚至 Snowflake 时代，但现在是弯道超车的最好机会，且中国有最好的具身智能场景和数据。

## 金句
> 我们的使命，就是把这些参差不齐的数据源源不断、高效地投放到 GPU 上，别让 GPU 因为数据读不上来而空转。
