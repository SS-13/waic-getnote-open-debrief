- 以 LangFlow 的高危 RCE 漏洞（9 分级）为例：安全公告发出后 20 小时线上就出现真实攻击成功案例，25 小时数据即被窃取——安全必须做在事前。

- 事前做全资产识别（基础设施/模型/应用）与风险检测（已上线 150 家组件漏洞检测），并用 AI 推理对 Agent 持续做渗透测试；事中围绕 Agent Loop 做全链路攻击溯源。
- 每个 Agent 都要像人一样被分发身份、做权限管控；安全防护要以 AI Native 原生方式融入 infra、模型、应用三层，让企业以最小成本获得最高收益。

## 内容整理

### 风险有多快：从漏洞公告到数据被窃只需一天
今天 Agent 已经融入生活的方方面面，但当它快速发展时，如何构建一个可信的智能体、让它真正帮助业务增长与提效，是必须回答的问题。先看一个数字：2026 年已经产生约 20 个 Agent 漏洞，其中 9 个以上是高危漏洞——所谓高危，是指现在就可以把 Agent 所运行的环境直接攻破。以最近的 LangFlow 漏洞为例，它是 9 分级：LangFlow 常被用来搭建 Agent 框架，而它外部 UI 里存在一个 RCE 漏洞；当安全公告发出时，20 小时线上就已产生真实攻击成功的案例，25 小时数据就被窃取。监管机构也给了很多指导，如网信办发布的 Agent 指导框架、Open Cloud 提出的「六要六不要」、欧盟的 AI 法案等。

### 「一加二」体系：一个平台 + 两大核心
我们把能力落在阿里云安全产品体系中，概括为「一加二」。**一**是 Agent 安全中心，一个平台型产品：
- **事前**：围绕基础设施、模型、应用做全资产识别；识别之后发现其使用的中间件、组件对应的风险，已上线针对此类漏洞的 150 家检测；同时提供 AI 推理能力，对 Agent 持续做渗透测试，帮助更快发现安全风险。
- **事中**：围绕 Agent 全链路，与云原生的 Agent Loop 做整体日志打通，基于 Agent Loop 做全链路攻击行为的溯源，并在事后做分析还原与深度检测。除 Agent Loop 日志源外，还提供一个可直接集成到 Agent 里的 Rust 插件，做到实时日志采集与洞察。

**二**是两个核心。第一个核心是**身份**：身份必须在事前规划，才能在 Agent 上线后让每个 Agent 都有对应身份、像对人一样做身份权限管控；我们构建的 Agent IDaaS 会给每个 Agent 分发身份。第二个核心是**三层防护体系**——Agent 安全需要从 infra 层、模型层、应用层三层防护，缺一不可；只做其中一两项，就不是一个完整的体系，安全风险敞口永远敞开。而要打造这套三层体系，「安全外挂」在落地上成本极大，因此必须以 AI Native 原生方式融入 infra、模型、应用之中，让企业以最小成本获得最高收益。

### 已在落地：私有化与安全运维 Agent
这套体系不是停留在 PPT 上。经过阿里云十多年安全的沉淀积累，我们把原有的十多个安全产品都以私有化形式上线到阿里云官网：用户既可通过自己的 Agent、也可通过三方 Agent 来使用。上线后已有 300 家用户，每天调用量达 50 多万次。我们还为中小用户提供了一个安全运维 Agent 平台，可直接在上面做漏洞分析、报告生成，以及持续的安全监测与自动化响应。无论是「用 Agent 去管安全」，还是「帮助 Agent 提前做安全防护」，目标都是一起构建可信赖的智能体。
