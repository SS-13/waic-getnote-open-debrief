## 一句话概要
莫非提出"组织级 AI"理念，并发布全托管 Agent 基础设施 QCloudAgents（QCA）：用一整套 Harness 工程把散落的个人 AI 收敛成统一在岗、持续沉淀的组织智能，靠"脑手分离"架构解决无人值守、规模并行、安全隔离与商业化落地。

## 核心观点
- 当下"人人都在用 AI，却拼不到一起、也带不走"，个人用 AI 的经验难以沉淀为组织资产，因此需要**组织级 AI**——独立身份、长驻云端、共享一份组织记忆，成为组织的"一等公民"。
- 组织级 AI 对内是成本中心（效率引擎），对外是收入引擎（嵌入硬件/软件/App 对客服务），同一套底座支撑两类场景。
- 从"人人用 AI"跨越到"组织级 AI"，中间隔着一整套 Harness 工程，可拆为五点：好用的 Agent Loop、无人值守、规模并行、隔离与安全、商业化。
- QCA 采用"脑手分离"架构：脑（规划、编排、推理、记忆、验收、观测，7×24 在线）与手（执行与工具调用的沙箱/企业环境）解耦，模型、执行环境、业务 Agent 三者可各自升级替换。
- 计费只发生在与 Agent 的真实交互中（模型成本 + 沙箱运行的硬件消耗），配置 Agent 平面本身不花钱。

## 内容整理

### 为什么需要"组织级 AI"
莫非以业界近期在 Slack 中发布、可 @ 唤起协作的 AI 成员类产品（转写为「CloudTag」）为切入，指出其背后是人与 AI 交互范式的变化：从被动执行变为主动执行（@ 一句"帮我跟踪这个任务"，它会在合适时机长程观测并主动把信息回传频道）、从单人变为多人协作等。过去员工的经验会随人离开而流失，所以他主张把散落的人工智能"收敛成统一在岗、协同一致、持续沉淀的组织级智能"：让 AI 拥有独立于人的身份、长驻云端、共享一份组织记忆，并把个人记忆有效沉淀为组织资产。

### 中间的 Harness 工程：五个要点
莫非把从"个人用 AI"到"组织级 AI"的跨度归纳为五点：① **Agent Loop**——决定何时中断/续跑、如何协同、模型如何路由、断点如何续传；② **无人值守**——生产级 AI 需 7×24 在线，可被定时任务、Webhook、IM 事件触发，不能是"半夜要人重启"的 Agent；③ **规模并行**——成千上万客户涌入时的数据与记忆隔离、成本优化，扛不住就排队、闲置又抬高成本；④ **隔离与安全**——A 客户读到 B 客户数据就是安全事故，各环节需检测验证；⑤ **商业化**——如何对外发布上线，让底座同时支撑对内提效与对外服务。

### QCA 的架构与落地
产品架构分"脑"与"手"两层：脑负责规划、编排、推理、记忆与验收/观测，7×24 在线；手是真正的执行与工具调用环境，提供云端各类 sandbox，也可把企业内部服务器接入作为执行层，并打通 MCP 渠道访问企业内容。这种脑手分离让模型可升级、执行环境可替换、业务 Agent 可持续优化，三者不必绑定在同一环境（讲者称与业界一些一体式方案如 Claude、Hermes 不同）。**成本**上，配置 Agent 不花钱，费用只在交互时产生，由模型成本与沙箱硬件消耗构成。**身份**上提供"组织—模板—终端身份"三级体系，无需为每个终端用户维护"记忆放哪"的复杂映射。**记忆**以 file-based 方式像代码一样被管理员/组织手动维护，并支持夜间自动"追忆"把个人记忆沉淀为组织记忆，均可通过 API 开关。**安全**上每次会话用独立临时沙箱、用完即释放，互相隔离；面向政企金融提供 BYOC（自带线下机器搭建组织级 AI）。案例方面：用 Q 系列工具（含 IDE）做自研，形成"自主发现 bug、修复、提 PR、人工审核后合入"的自动化闭环；QCA 接入客服助手实现 7×24 无人值守，问题分析从 30 分钟缩短到 2 分钟；产品团队让它每晚汇总客户需求并按产品审美排优先级、生成 PRD，把 loop 跑起来后"又可以摸鱼了"。

## 金句
> 组织级 AI 其实就是把散落的人工智能，收敛成统一在岗、协同一致、持续沉淀的组织级智能；对内它是成本中心，对外它又是收入引擎。
