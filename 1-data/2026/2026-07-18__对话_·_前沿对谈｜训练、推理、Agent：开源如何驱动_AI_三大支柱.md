## 一句话概要
围绕 AI 的三大支柱——训练、推理、Agent，两位从开源生态视角交流：硬件与软件架构正同时剧变、唯有开源大规模协同才能应对；Agent 时代「模型不再是一切」，价值正从「用最好的模型」转向「按结果（outcome）付费与评估」。

## 对话背景
Mark Collier 已来中国约 16 年，2010 年发起 OpenStack，从事开源约 20 年，如今专注于 PyTorch Foundation；基金会同时支持 vLLM 等项目，几天前刚在上海办了一场很受欢迎的 vLLM meetup。PyTorch 被超过 90% 的实验室和公司用于训练模型，是训练领域久经验证的最佳软件；推理侧则支持 vLLM。李飞飞代表阿里云与其交流训练、推理、Agent 三个环节的最新趋势与合作机会。

## 讨论的问题
1. 从 PyTorch 社区看，训练领域的最新趋势是什么？
2. Agent 时代有哪些关键转变？北美市场有何观察与建议？
3. 按结果付费（outcome-based）会如何重塑软件与模型的价值？
4. PyTorch Foundation 在 Agent 领域有哪些进行中的工作？

## 各方观点

### 一、训练趋势：加速器爆发与「同时剧变」的协同挑战
- **Mark Collier**：一个很有意思的现象是 AI 加速器（AI accelerator）种类在快速增长，刚才也听到阿里云在硬件侧的新创新。从数据中心、内存带宽瓶颈等角度看，训练正在不断突破极限；要让一款 AI 加速器真正用于训练模型，在 PyTorch 里有良好支持至关重要。基金会为此设有「多架构工作组」，支持开发更多不同的后端（backend）。
- **Mark Collier**：更独特的是，如今硬件与软件的架构在同一时间剧烈变化——我们在全球范围内既要改变软件架构（新的模型架构），又要改变硬件，而应对这种巨大协同挑战的唯一方式就是开源。例如 vLLM 和 SGLang 对新模型能做到「zero-day 支持」（如 Kimi 等一上线即支持），全天候跟进。

### 二、Agent 时代：模型不再是一切，token 也不等价
- **Mark Collier**：今年 Agent 迅速崛起并「接管」了很多场景，驱动了更多 token 生成；但要问它究竟在做什么。前面有讲者提到「token productivity（token 生产力）」，这个说法很好——因为并非每个 token 都等价。人们正在意识到的一个转变是：**模型不再是一切**。模型仍然极其重要，但你不必对每一次 API 调用都用「最好的模型」，而应为特定任务、特定调用使用「最合适的模型」。
- **李飞飞**：认同这一趋势——为给定任务、给定 API 调用选择最合适的模型，正变得越来越重要。
- **Mark Collier**：另一层是个性化上下文。他试用了若干开源 Agent 系统，最近也开始采用 Hermes agent 这类方案——把个性化上下文存储在本地或自己的私有系统里非常重要。未来我们会走向一个「Agent 的使用本身会反过来改进整个系统」的世界：无论是直接反馈到模型训练，还是把更多上下文喂回个人系统，你自己的系统都会因你的使用而越来越聪明。

### 三、从「按资源」到「按结果」：outcome 重塑价值
- **Mark Collier**：会出现一种「以结果为导向的市场（marketplace of outcomes）」——一旦有人采用并喜欢，采用率可迅速升到 70%。企业将用各自的评估框架（evaluation framework）来判断哪一个（或哪一组）模型最能达成「客户为之付费的结果」，从而让技术被市场需求拉动。
- **李飞飞**：这与 SaaS（软件即服务）行业一致——企业为 SaaS 订阅付费，是按结果（outcome）付费，而不是按 CPU 周期、内存用量等资源消耗定价。
- **Mark Collier**：一个公开案例显示，在完全相同的硬件上，仅靠软件优化就把推理吞吐提升了约 3 倍。这说明我们做的工作在经济上极具价值——当大家一起把推理做得更高效，经济飞轮就会转起来，从而持续加大投入、不断优化基础设施侧的技术栈。

### 四、PyTorch Foundation 在 Agent 领域的工作
- **Mark Collier**：从基金会视角看，社区对「如何训练模型以更好地服务 Agent」的兴趣越来越浓。今年 9 月初，PyTorch Conf 与 Agent Conf 将一同在上海举办，敬请关注。
- **李飞飞**：建议促成 vLLM 团队与相关伙伴合作、并纳入 PyTorch Foundation，愿意牵线搭桥；期待在 PyTorch Foundation、Agent AI Foundation 与阿里云之间建立更强的合作伙伴关系。

## 金句
> 并不是每一个 token 都是等价的——所以「token 生产力」是个很好的说法。
> 模型不再是一切；关键是为给定任务、给定 API 调用，用最合适的模型，而不是最好的模型。
> 硬件和软件的架构在同时剧变，而应对这种大规模协同挑战的唯一方式，就是开源。
> 企业为 SaaS 付费，是按结果付费，而不是按 CPU 周期、内存用量这些资源消耗来定价。
