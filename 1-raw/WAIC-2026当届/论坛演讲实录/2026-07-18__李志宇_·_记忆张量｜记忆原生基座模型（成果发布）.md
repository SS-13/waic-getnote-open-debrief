- **论坛**：记忆张量·从一次性 Agent 到记忆原生智能时代论坛
- **时间**：2026-07-17 · 9号会议室 · 成果发布
- **嘉宾**：李志宇（记忆张量，CTO）

## 一句话概要
从「know（知道）」走向「remember（记住）」，发布记忆原生基座模型的探索——把记忆机制内化于模型的架构、状态、训练目标与推理机制，让模型在真实生产中基于记忆持续学习、成为可自我成长的智能体。

## 核心观点
- 大模型已能较好处理「know」（知识以预训练参数形式存入，配合窗口、RAG 与工具调用），但更重要的是「remember」。
- 「remember」至少要求模型做到三件事：保持长期状态（任务与环境的连续状态）、具备记忆操作能力、以及自主的记忆运行时管理。
- 记忆原生基座模型的定义：将记忆机制内化于模型的架构、状态表示、训练目标和推理机制当中的基座模型。
- 三个典型特性：状态原生（把历史偏好、历史信息、任务进展内化到模型内部状态）、与推理计算流强耦合、面向记忆的端到端优化。
- 训练关键：构建多步交互式记忆数据（记住/更新/遗忘/反思），把「原生推理」与「主架构推理」做 fusion，在计算流中以残差形式融入原生记忆。

## 内容整理

### 从 know 到 remember
在「know（知道）」这件事上，很多知识以预训练参数的形式放入模型已有的参数空间，使用已发布的基座模型时再把信息放进上层窗口做联合推理，并用 RAG 与工具调用进一步增强。但除了 know，还有一个更重要的场景是「remember（记住）」。对 remember，模型至少要完成三件事：一是保持较好的长期状态，包括任务与环境的连续状态——随着 Agentic 系统支持的任务时间越来越长，长期状态保持的重要性越来越高；二是具备记忆的操作能力（当前很多框架靠明文的 agentic 方式管理）；三是让平台提供记忆的治理与基础设施、基模提供推理与运行时的管理能力。

### 什么是记忆原生基座模型
用一句话定义：能够将记忆机制内化于模型的架构、状态表示、训练目标和推理机制当中的基座模型。它至少具备三个典型特性：其一状态原生，能把用户的历史偏好、相关历史信息与任务进展内化到模型内部状态；其二与模型未来推理时的计算流做强耦合；其三面向记忆的优化能端到端进行，而非为每个场景单独优化。围绕这一目标，在现有框架下有三个最核心的问题：记忆的表征（记忆原生语义下应如何表征、哪些内容需要存储与关注）、记忆的进化（模型完成记忆原生化训练并部署后，与业务场景的 Agent 交互，把交互推理流融合进原生记忆表征、辅助下一次推理获得更好效果）、以及记忆的原生操作应由模型自主学会而非预先定义。

### 训练框架与推理融合
研发上，由 local memory block 与 helper memory block 协同完成增删改查操作，产生的信息存入 local memory block、供未来推理使用。整套训练大致分三步：第一步构建多步、交互式的记忆数据，典型操作流包括如何记住、更新、遗忘、反思，覆盖用户涉及记忆的各种场景（例如用户说「请记住我明天开会时间是九点半」，希望这句话被内化为模型的操作流程）；第二步确定训练目标——为避免上层网络越变越长导致成本与 token 不可控，构建两条推理路线：原有主架构推理与记忆原生推理，后者与 memory state 中存储的原生记忆状态交互（由 helper memory block 执行），再把 original 推理与 memory 推理做 fusion，从而在推理计算流中引入原生记忆信息；概括为三个阶段——写入记忆（commitment）、读取原生记忆模块、以残差形式融入记忆推理流程。

### 评估、演进与飞轮
认为现有的记忆评估框架与流程不足以支撑「记忆原生基座模型」这件事。例如一段多轮长对话中用户反复改名字，传统评估只要模型最后答对名字就算 OK，但这并不足以衡量真实的记忆能力，需要更细致的评估机制。从演进看：去年前后做 Memory 框架，本质是让记忆的编排与治理高效、可控地执行；如今做记忆原生基模，本质是让模型在真实生产环境中基于记忆创造出可持续学习的状态，真正成为可自我成长的智能体。之所以能推进，靠两个飞轮：大量真实部署的记忆场景，以及高请求量的云服务平台——由此了解模型真实的记忆操作属性，让数据飞轮与模型飞轮相互关联迭代，目前每次可有效新增 20B token 以上的训练量，快速满足模型迭代。更多实验结果可扫码下载技术报告。
