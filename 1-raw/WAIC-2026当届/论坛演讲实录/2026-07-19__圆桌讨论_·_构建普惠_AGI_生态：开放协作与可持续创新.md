- **时间**：2026-07-19 · 上海·518 会议室 · 圆桌讨论
- **嘉宾**：庄明浩（"途中之书"主播，主持）、赵俊博（浙江大学，博士生导师）、顾奇（美团 LongCat 团队，开源大模型主任研究员 / 通用 Agent 团队负责人）、徐文彬（LobeHub，创始人）

## 一句话概要
一场从"当下模型技术研究"聊到"agent harness 与协议"的对话——学界受限于算力只能避开 scaling、业界共识转向 long-running，而无论学界业界的议题都汇流到了 agent 的 harness 与系统设计上。

## 核心观点
- 学界视角：算力受限使 scaling 类研究"不太被推荐"，汇报低于约 30B 的结果参考意义有限；高校要么与公司合作，要么做能撬动更大空间的特异化/应用型工作。
- Claude Code / 长任务出现后，行业重心从"scaling"转向 long-running，coding 与办公生产类任务被更深耕耘。
- 长任务给评测带来大难题：跑一周怎么评？PRM/process reward 这类设计"大道至简"、当前未必需要；模型迭代与 harness 设计高度耦合。
- 用闭源（如 Claude）驱动的问题在于不透明、"教师力度"不可控、与自己的设计不一定对齐，厂商需要能自己掌控在哪里加/不加强化。
- 普通用户场景下纯 coding 式交互体验不够：文档要能在线编辑分享、长任务要能拆成可无限级联、可用不同模型的子 task 来管理。
- 2026 年国内头部模型厂商与大厂已从 Chatbot 战场进入 Agent 战役，聚集了大量聪明人推动方向快速进展。

## 内容整理

### 主持人搭台：学界、业界、开源三个身份
庄明浩（做了一档叫"途中之书"的博客、长期关注 AI 行业）先做架构性介绍：三位嘉宾各代表一个身份切面——赵俊博（挂浙江大学博士生导师）代表此刻学术层面的技术研究状态；顾奇（美团 LongCat 团队、开源大模型主任研究员兼通用 Agent 团队负责人）代表业界较领先的模型厂商在做的事；徐文彬则代表开源应用侧。顾奇补充自己来美团前一直在做从 reasoning 到 RL、早期具身智能等，算法模型与产品系统都有涉及。徐文彬自我介绍在做 LobeHub——一个做了约四年、约 80K star 的开源应用，他去年出来全职创业，此前在蚂蚁做实验室，笑称今天"算是回娘家"。

### 学界避开 scaling，业界转向 long-running
第一个话题聚焦当下的模型技术研究。赵俊博从学术立场说，任何跟 scaling 相关的东西其实"不太被推荐"：看论文时若最后只汇报低于约 30B 的结果，参考意义就不大——算法再 fancy，真上了规模要考虑的事情（尤其数据层面）就完全不同，很多问题在小规模上根本不出现；受限于实际算力，高校想做更大规模也很难，因此要么与公司合作，要么去做没跑 scaling 的、偏应用或特异化的工作，先有一个 basis 再撑开更大的空间去覆盖更多任务。他还观察到，自 Claude Code / 长任务概念火起来后发生了两个变化：一是 coding、办公等少数明确且重要的任务值得更深钻研；二是大家的注意力被牵引到 long-running 上——从今年三月起所有人都在讲 long-running，"scaling"几乎无人再关心，这是一次不小的跃变。

### 长任务的评测与"自己掌控"的必要
顾奇顺着说，模型能力推演会更聚焦两点，其一就是 coding。谈到长任务，赵俊博指出轨迹会越拉越长（能跑一天 OK，但跑到一周，多级 memory 的压缩、逻辑拆分、升级都会出问题），也给评测带来大难题——"我跑一礼拜咋评？"而此前大家讲的 PRM、process reward 这些分数，如今看来"大道至简"，他这边并不太需要。他强调模型迭代与 harness/训练高度耦合：用 Claude 这类闭源会觉得不够、不透明——不知道它加强/削弱了什么、与你的设计不一定对齐，还可能在你觉得不必要的地方加了过多强化，反而对训练有不好的影响；因此厂商必须能自己掌控"在哪些地方加、在哪些地方不加"强化。顾奇补充，当前 harness 多围绕 coding 场景设计，但普通用户纯 coding 式的交互体验并不够：写文档时生成一段 Markdown 其实不太能看，最好能直接绑一个可在线编辑、可分享的文档；长程任务若像 CC/Codex 那样一个指令 go 出去，中间没法管理，更该能拆成可无限级联的 task、每个 agent 把子任务分配到不同 task、甚至不同 task 用不同模型来 plan。他从"用户需要什么、用户体验"出发，认为在模型给定的前提下，如何提供足够好的工具设计、上下文设计与交互，是一个偏系统设计的命题。

### Agent 战役与年底里程碑
庄明浩指出，2026 年国内头部模型厂商与互联网大厂已从 Chatbot 战场进入"Agent 战役"：腾讯有 CloudBase 等、字节豆包专业版在推 Agent、阿里有 Coder/木兰 Run/悟空（现已合并）、飞书也在推自己的 Agent。徐文彬回应，这个领域已聚集太多聪明人，大家一起做一件事时会快速推动某个方向的进展；大厂看到高经济价值后纷纷推内部基建，并试着从 coding 延展到日常办公、再到更广的白领工作。最后一问是"到 2026 年底期待看到什么"：赵俊博说希望模型能连续跑两礼拜、长驻任务不停；顾奇说今年 focus 仍在 long-running，希望三到六个月内有相应模型产出后，产品能给用户很好的交互去承载长任务管理；徐文彬呼应——信任是像从 Claude Code 写一点代码、到写一个需求、再到做一个大项目那样一点点积累的，他希望自己的产品能承载让用户从小任务走向巨长程任务的能力。
