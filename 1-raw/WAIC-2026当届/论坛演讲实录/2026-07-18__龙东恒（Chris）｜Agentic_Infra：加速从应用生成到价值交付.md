## 一句话概要
AI 已把应用生成从几个月压缩到几小时，但真实业务系统不会因「代码交付了」就上线；产品 And 要从生成代码的 Coding Agent，升级为真正交付业务价值的 Delivery Agent，靠的是把云资源交给 Agent 来「可理解、可调用、可治理、可审计」地使用。

## 核心观点
- 过去一年 AI 已将应用生成从几个月缩短到几周、几天甚至几小时，但真实业务系统的交付还需要基建与长期经营的知识。
- Coding Agent 只解决代码生成，忽略了云服务基建与长期经营所需知识——这些才是业务快速隆起、持续运营的关键；And 由此升级为 Delivery Agent。
- 云资源的使用方要从「code」转变为「agent」：人可以不懂 infra，但 agent 必须懂 infra，且 infra 对 agent 必须可理解、可调用、可治理、可审计（内部戏称「小阿里云」）。
- Agent Infra 的精华，是把 Git、sandbox、runtime 及 checkpoint/provision 等特性组织成一条「可恢复、可审计」的动作链——像游戏的 SL 大法（存档读档），把试错成本降到无限低。
- 交付 Agent 要「有量、也有速度」：创建实例、唤醒新端机可做到一秒左右，让用户从提出需求到拿到结果没有断点；成本上按用量付费。

## 内容整理

### 从应用生成到价值交付的判断
过去一年，AI 已经把应用生成从几个月时间缩短到几周、几天甚至几个小时；但真实的业务系统不会因为代码交付了就自动上线。我们的产品布局分两侧：左侧是创意与营销——FreeMind 是一体化的创意与营销工作室，Comfast 是数据驱动的 AI CMO；右侧是软件与游戏——And 负责软件的创造与交付，Compose 负责把游戏创意变成可实际游玩的产品。这些产品看似服务不同场景，本质关注同一件事：AI 不只是承担内容生产，而是要把真正交付的结果交付给用户。今天重点聚焦 And，看它如何从生成代码的 Coding Agent，转向真正交付用户价值的 Delivery Agent。

### And：一次能力边界的升级
Coding Agent 解决的是代码生成，但忽略了云服务基建以及长期经营所需的知识——而这些才是业务快速隆起、持续运营的关键。为此 And 在代码之上做了更强的延伸，为客户提供相对完善的企业服务。Agent 依然是所有交互的起点，但我们同步配套更多服务，比如 infra，我们内部戏称「小阿里云」。要解决服务的易用与可控性，就意味着要把云资源的使用方从原先的 code 转变为 agent：人可以不懂 infra，但 agent 必须懂 infra，同时 infra 对 agent 必须是可理解、可调用、可治理、可审计的。

举例：用户说「帮我做一个点菜系统」，我们要做的其实不是把网页做出来，而是把数据库提起来、把域名分配好、把网站部署上线——这是一套系统性的动作。我们的实现分三层：第一层是**表达价值**，即用户在产品中可见的功能板块；第二层是最重要的一趴，**end agent 承上启下**，掌握最多上下文，既最懂业务、也最懂 infra；第三层向下看，**agent infra** 的精华在于 Agent 不是去调用某一个单点工具，而是把 Git、sandbox、runtime 类似的服务，以及其下 checkpoint、provision 等特性，统一组织成一条可以被恢复、可以被审计的动作链。

### 三个价值：可恢复的试错、效率、成本
Agent 可以在任意时间节点生成当前控制面与数据面的「前面节点」，并在后续任意时间恢复到该节点——这点像打游戏的 SL 大法（存档与读档）。当错误修正的成本无限降低，我们就可以加大鼓励创新的力度，更快交付、更多试错、更接近成功。第二个价值是**效率**：在对话式产品里，用户等待的不是一个数据库被创建，而是业务系统被交付——我们创建一个实例不需要一秒钟、新开一个端机大概一秒左右，用户从提出需求到拿到结果是没有断点的，而速度往往是新用户转化的第一个体验。第三个价值是**成本**：云资源必然走向「用多少量、付多少钱」，应与模型按用量付费保持一致，因此要做灵活。为此 And 还完善了单租、多租以及无缝迁移的一整套弹性数据底座，并希望把规模、安全、成本与 SLA 沉淀为可复用的最佳实践，在行业中推广。

### 目标
我们希望最终实现的是：Agent 的用户在这里提出一个目标，我们就把它完整地交付给用户。

## 金句
