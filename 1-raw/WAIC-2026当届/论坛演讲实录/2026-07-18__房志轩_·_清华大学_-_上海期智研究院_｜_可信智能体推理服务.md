- **时间**：2026-07-18 · 金厅C · 主旨演讲
- **嘉宾**：房志轩（清华大学、上海期智研究院助理教授 / PI；工作聚焦可验证、可审计的智能体推理框架）

## 一句话概要
为智能体调用远端大模型解决两大信任问题——验证"模型是不是它声称的那个模型"，以及保障交易交付"一手交钱一手交货"，并做到轻量到笔记本也能运行。

## 核心观点
- 当前"影子 API"泛滥：审计发现至少 17 个影子 API 被 187 篇以上学术论文使用，近一半模型并非服务商声称的前沿模型。
- 传统验证依赖额外硬件、零知识证明、区块链或用户侧 1:1 复现，成本高；他们做到接近生成速度、毫秒级的轻量验证。
- 用一个"秘密"把交付与交易捆绑（PACE 框架），使计算方"不给结果就拿不到钱"。
- 目标是按"有效、高质量用量"付费，而非预付订阅式地把风险转嫁给用户。

## 内容整理

### 问题一：模型是不是真的
第一个问题是如何相信 API 背后的大模型。最近一份第三方审计报告指出：至少 17 个影子 API 已被超过 187 篇学术论文使用，而这些论文并不清楚 API 背后是什么模型；审计测试后发现将近一半的模型并非服务商声称的前沿模型（指纹、输出结果都存在巨大差异）。传统服务验证方法往往依赖额外硬件、服务商额外证明（如零知识证明、区块链）或用户侧 1:1 复现——用户要在本地把同样的推理跑一遍，成本高。团队的方法能实现接近生成速度的验证，甚至在一台 16G 统一内存的笔记本上也能做到相似性验证。

### 问题二：交付与交易的安全
第二个问题是如何保证整个交易、交付过程安全可信。当前多为用户预付费订阅 AI 服务，相当于把风险转嫁给用户——用户既不知道会得到什么服务，也不知道实际会用多少；而其他按量付费方法（如 x402/L402、基于区块链状态通道）并不内生"质量服务验证"模块。团队提出 **PACE 框架**：用一个秘密把交付与交易捆绑——计算方把结果加密传给购买方，购买方用同样的秘密锁定一笔资金；实现方式是基于区块链链下支付通道，支持高频次、低额度、长时间的支付，契合智能体支付模式。这样可保证计算方不可能"不给结果就拿到钱"。验证层非常轻量：购买方只用毫秒级时间，而开源模型在 A100 上要数秒，因此可支撑长时间、大规模、持续的按量高质量交付，不实质影响系统性能。

### 智能体支付的全景
更通用的智能体支付是一个四环链条：端侧先判断"我是否需要额外算力/资源"（路由选择，今年的一项工作）→ 进入质量验证 → 安全交付（买卖双方一手交钱一手交货）→ 未来智能体进行真实世界商品交易（当前只是 token 交易）。链条前后还有更多问题，例如在开放世界下由不同组织机构、不同个人所拥有资源的身份与可信问题。

## 金句
> 我们希望做到的是，按照有效用量、按高质量用量来付费，让买卖双方能够一手交钱一手交货。
