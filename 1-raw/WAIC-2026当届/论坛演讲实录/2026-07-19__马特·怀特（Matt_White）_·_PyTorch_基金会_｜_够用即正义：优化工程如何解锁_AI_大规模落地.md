## 一句话概要
"堆算力"已撞墙，源自中国的优化工程正用更小的模型、网关路由与缓存，以"每美元买到多少智能"重新定义企业 AI 的性价比。

## 核心观点
- "compute up"（一味堆算力堆数据）范式已经撞墙，不能把 token 和算力当作无限资源。
- 真正该衡量的是"每一美元买到多少可用智能"（dollar per intelligence），含重试、失败、人工复核与编排开销，而非每 token 成本或榜单分数。
- 企业已从"人人用 AI、token max"转向控成本：Uber 5000 名工程师的 coding 工具预算被提前耗尽后开始限额，Tesla、Amazon 等纷纷跟进。
- 靠开源权重模型 + 智能网关路由 + 缓存 + 上下文裁剪，可在不设死限额的情况下把成本压下来（缓存命中率从约 5% 升到 60%）。
- 开源权重模型（如 GLM 5.2、Kimi K2.7、2.x 万亿参数级）已接近前沿，且成本远低于闭源 API。
- 用"六步法"把前沿智能带进真实产业。

## 内容整理

### "堆算力"撞墙，优化工程从中国走出
Matt 开场自嘲身体抱恙、又倒了四天时差，要多依赖讲稿。他指出，长期以来行业活在"compute up"范式里——更多算力、更多数据——如今已撞墙，不能再把 token 和算力当作取之不尽的资源，靠堆规模通往能力并不可行。好消息是有替代路径，而且正是源自中国：优化工程。美国持续在模型训练、RLHF、mid-training 上堆算力，而中国的开放实验室在训练侧和推理侧都极擅长挖掘优化空间。由此他引出一个更合理的度量——从经济和企业实践角度看，"每美元买到多少智能"比"每 token 成本"更有意义。

### 从 token max 到控成本
18 个月前企业的口号是"让所有人都用上 AI"，公司内部搞起排行榜、比谁 token 用得多，"token maxing"一度成为热词。但 Uber 去年 12 月给 5000 名工程师铺开 agent coding 工具，到 4 月就把整年 2026 预算耗尽，如今对每位员工设限；Tesla、Amazon 等也在跟进——大家意识到在算力/token 上花钱太多了。可 token 用量仍在指数增长，怎么做到的？靠的不是限额（Coinbase 91% 的工程师从没触及上限），而是几招组合：一是用开源权重模型，Coinbase 把 GLM 5.2 和 Kimi K2.7 设为内部 LLM 服务的默认；二是智能网关，按任务把请求路由到合适的模型，只在复杂推理时才调用前沿 API；三是缓存，命中率从约 5% 升到 60%（约 12 倍提升），并辅以上下文裁剪。价格上，GLM 5.2 的进出成本约 1.4/4.4 美元每百万 token，而 Claude 4.8 要贵得多。

### 开源权重的经济学与六步法
Matt 强调如今小模型已相当好用、中模型也不错，而 2.x 万亿参数级的开源模型已在前沿水准；开源权重给了两条闭源 API 无法竞争的经济路径——本地/边缘部署，以及借 Fireworks、Together AI 等推理服务商（它们在价格上竞争并自带优化）来服务模型。他留给听众一个度量：以"每美元的可用智能"来算账，把重试、失败、人工复核和编排开销都算进去，而不是盯着每 token 价格或榜单（后者只在规划、初筛模型时有用）。落地则有六步：一，拆解——把工作流拆成有边界的任务（往往有大量可缓存、可确定化的重复任务）；二，适配——每个任务映射到能过质量线的最小模型，需要时再升级到中模型或前沿；三，在网关做路由与缓存（否则等于白白把钱留在桌上）；四，少升级——只在低置信、schema 违规或失败步骤才调前沿 API；五，守护循环——设最大步数、工具权限范围、跨模型校验和注入防御；六，按"每完成任务、每路由的美元成本"度量并持续迭代。这场分享的主旨，就是开放基础设施如何把前沿智能带进真实产业。
