# 半数字化企业中的业务翻译与最小闭环假设

## Claim

在业务对象、数据来源、规则、权限和异常责任尚未显式化的半数字化企业中，FDE 的第一步不应是部署通用 Agent，而应先将分散的工作痕迹还原为可审计的业务对象、流程和责任边界，再选择高频、边界清楚、结果可验收的工作建立最小可运行闭环。

## Evidence

- 飞书社区《FDE 人才白皮书》用 Excel、群聊、纸质单据、口头沟通和资深员工经验说明业务事实与判断规则可能尚未结构化；其报价例子提出输入、规则、动作、人审、写回和异常接管的最小闭环。[来源解读与评分](../_indexes/SRC-Q003-18-飞书社区FDE人才白皮书-解读与蜂巢评分.md)
- OpenAI 的 FDE 与 Technical Deployment Lead 岗位公开描述以 discovery、工作流/成功标准映射、范围界定、生产上线、采用和评测反馈为交付顺序。[OpenAI FDE](https://openai.com/careers/forward-deployed-engineer-(fde)-sf-san-francisco/) [OpenAI TDL](https://openai.com/careers/technical-deployment-lead-forward-deployed-engineering-(fde)-sf-san-francisco/)
- WAIC 企业材料把业务原生、组织原生、工程原生、运营原生、知识底座、评测观测、权限和运行治理视为企业 Agent 前提；它们提供能力信号，不证明所有企业都处于同一成熟度。[腾讯云](<../../../1-raw/WAIC-2026当届/论坛演讲实录/2026-07-18__吴运声_·_腾讯云_｜_以知识驱动企业原生智能体，构筑专属竞争力.md>) [阿里云](<../../../1-raw/WAIC-2026当届/论坛演讲实录/2026-07-18__周琦_·_阿里云｜Agent_Native_Cloud：让智能体成为企业原生的能力.md>)

## Boundary

这是一条部署假设，不是对中国企业整体数字化程度的统计判断。数字原生企业或已有成熟业务本体、系统和权限体系的企业，可直接从集成、应用构建和评测优化开始。该假设需要用独立项目结果检验其对采用、维护成本、人工接管和业务收益的影响。
