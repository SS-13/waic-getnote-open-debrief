# FDE 中美企业 AI 部署与治理产业研判

## 当前判断

FDE 的本质不是“更会写代码的顾问”，也不是把一堆 Agent 安排进企业，而是把企业的业务目标、数据、系统、权限、模型、人的决策和持续运营连接为可验证的生产系统。工程是底座，业务结果、采用、风险与可复用性是验收单位。

美国已经出现较清晰的组织分工：FDE 交付系统，技术部署负责人连接业务目标、变革与 ROI，平台角色把跨客户模式沉淀为产品能力。中国在 WAIC 的连续资料中已经看到相同的能力要素，从 RPA 的流程发现到 AgentOps、知识底座、统一身份权限、评测观测和运行成本；但这些能力仍更多被云厂商、集成商、行业软件和企业数字化团队分担。中美差异首先是组织产品化与责任链的差异，不是“是否会做 Agent”的二元差异。

## 企业 AI 部署的正确顺序

`价值流/决策权 -> 业务本体 -> 数据与权限 -> 任务拆解 -> 自治分级 -> 工具集成 -> 评测与观测 -> 采用与 ROI -> 平台复用`

这个顺序避免两种常见失败：先买模型再找问题，或先画多 Agent 架构再补数据、权限和责任。业务本体的作用是让数据资产重新对应订单、设备、客户、合同、人员、风险事件等业务对象；它使 Agent 的读取、建议和行动能够有明确语义、授权和审计边界。

## Agent 应放在哪里

Agent 应按任务可验证性和风险/责任半径决定自治程度，而不是按模型大小或“智能体数量”决定。可重复、可验收、可回滚的低风险任务，适合有限自主执行；规则清楚但会影响资金、合规或重要客户关系的任务，应由 Agent 执行并由人审批；结果难验收的任务多为 Copilot；低可验证且高风险的任务必须人主导。详见 [K005](../concepts/K005-Agent自治与责任矩阵.md)。

## 五层治理

| 层 | 核心问题 | 最低控制对象 |
|---|---|---|
| 数据治理 | Agent 是否理解了正确、合法且最新的业务事实？ | 语义、质量、血缘、保留期、数据访问授权 |
| 模型治理 | 模型和提示是否在当前场景稳定、可靠且受版本控制？ | 选型、版本、离线/在线评测、漂移、安全测试 |
| Agent 治理 | Agent 能以什么身份、调用什么工具、做出什么行动？ | 身份、最小权限、工具白名单、记忆、审批、日志、熔断、回滚 |
| 组织治理 | 谁定义目标、接受结果、接管异常并承担后果？ | 责任人、验收、变更、事故响应、申诉与救济 |
| 资源治理 | 单位有效结果是否可持续？ | 质量、延迟、token/算力成本、并发、容量和能耗 |

## 中美比较的可用结论

| 维度 | 美国公开信号 | 中国 WAIC 与政策信号 | 不应作出的推论 |
|---|---|---|---|
| 角色 | OpenAI、Palantir 等公开命名 FDE/部署角色，并与产品、研究、平台协同 | 解决方案、实施、行业 AI、Agent 工程、云平台与数字化团队承担相近任务 | 职称不同不等于能力不存在 |
| 交付 | 强调从原型到生产、采用、ROI、评测和复用 | 强调从 demo 到确定性结果、流程融合、知识底座、统一治理 | 论坛功能不等于客户已规模化采用 |
| 产品化 | 明确把现场信号回流平台/模型/产品 | 出现技能、工具、策略、评估复用的 Agent 平台叙事 | 不能仅凭叙事判定复用率 |
| 治理 | 安全、GRC、权限和评测进入交付协作 | 身份、策略、网关、资产、沙箱、观测、成本成为显性议题 | 功能清单不等于合规或可靠性证明 |
| 制度环境 | 公司岗位定义与企业客户交付牵引 | “人工智能+”要求 AI 融入战略、组织和流程，并支持 AI 应用服务链 | 政策目标不等于当前普及率 |

## 对企业的含义

1. 不要把 FDE 招聘等同于雇一个“万能 AI 人”。至少需要业务负责人、数据/系统负责人、平台/安全负责人和变革/运营负责人共同承担责任。
2. 先选择高频、可验证、可回滚、能测 ROI 的价值流做第一个生产闭环，例如知识检索到工单草拟、质检到复核、报价到审批，而不是开放式“全能助手”。
3. 每个上线 Agent 必须有业务 owner、数据 owner、模型/平台 owner 和事故接管路径；没有这些，不应授予外部发送、写库、付款或设备控制权限。
4. 把成功项目中的连接器、业务语义、评测集、授权模板、监测面板和事故复盘沉淀为企业资产。是否形成这层复用，才是企业从项目制走向 AI 原生的分水岭。

## 仍未知

- 中美 FDE 的实际雇佣规模、薪酬与留存率缺少统一、公开且可比的统计。
- 中国企业中哪些岗位会最终收敛为 FDE 名称，仍取决于模型厂商、云厂商、集成商和客户之间的价值分配。
- Agent 的生产成功率不能用 demo、签约或单次效率案例替代，仍需观察续费、人工接管、事故、单任务成本和业务收益。
