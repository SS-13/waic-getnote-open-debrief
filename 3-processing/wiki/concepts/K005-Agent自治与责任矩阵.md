# Agent 自治与责任矩阵

## 定义

这是用于决定“AI 可以做什么、谁必须复核、何时必须停止”的部署框架。它不是给 Agent 编号或分层的组织图，而是把每个任务放入可验证性和风险责任半径构成的二维空间；任务频率与价值作为第三个优先级筛选条件。

## 二维矩阵

| 任务可验证性 \ 风险与责任半径 | 低：影响可逆、边界清楚 | 高：资金、合规、健康、安全或重要客户关系 |
|---|---|---|
| 高：输入、规则和结果可清楚验收 | **有限自主 Agent**：可在已授权工具内执行，保留日志、阈值、熔断和抽查。 | **执行型 Agent + 人工审批**：Agent 完成检索、填单、计算和建议，人保留最终批准、升级与回滚权。 |
| 低：目标模糊、结果难以客观验收 | **Copilot/探索助手**：提供草案、归纳、方案和模拟，不自动落库或对外行动。 | **人主导 + AI 建议**：AI 仅提供证据、备选方案和风险提示；关键判断、沟通和行动由责任人完成。 |

## 使用顺序

1. 识别业务价值流、关键决策、业务对象和责任人。
2. 盘点数据质量、权限、工具接口、异常处理和可回滚能力。
3. 将任务放入矩阵，设置允许的调用、审批点、预算、日志和停止条件。
4. 仅在高频、可衡量且收益高于治理成本的任务上，优先从 Copilot 逐步升级自治。
5. 用离线评测、影子运行、线上指标、人工接管和事故复盘持续调整边界。

## 不应如何使用

- 不以“多 Agent”数量替代流程设计。
- 不把模型能力提升自动等同于可放宽权限。
- 不把低风险的文本生成经验迁移到高风险、不可逆的外部行动。
- 不把一次 demo 成功当作生产授权。
